# sitewatch — мониторинг обновлений документации

Раз в сутки проверяет сайты из списка, находит новые и изменённые документы (страницы, PDF по ссылкам, Telegram),
просит агента (DeepSeek) разобрать их по-русски и присылает **один краткий дайджест на почту** строго по теме **«мясо и рыба»**:
по каждому изменению четыре строки — **что** изменилось, **где** менять, **как** менять, **к какому сроку**. Если обновлений
нет — письма нет. Дополнительно раз в сутки дёргает несколько методов вашей интеграции и считает ошибки в её журнале:
так видно, что API поменяли или отключают, даже если об этом нигде не написали. Новые сайты добавляются записью в
`config/sources.yaml` без правки кода.

## Как это устроено

```
sources.yaml → Fetch → Извлечение текста → Сравнение с базой (SQLite) → Агент-аналитик → Письмо
(страницы, PDF по                          хэш + diff, новые ссылки      DeepSeek, JSON  SMTP
 ссылкам, Telegram)                                                                        ↑
probes.yaml  → контрольные вызовы API ─────────────── сигналы ───────────────────────────┤
logwatch.yaml→ счётчики ошибок в журнале ──────────── сигналы ───────────────────────────┘
```

- **Скрипт** отвечает за «забрать, сравнить, запомнить»: дёшево и без галлюцинаций.
- **Агент** подключается только когда изменение найдено: выписывает из документа только мясо и рыбу и отвечает на четыре вопроса
  (что, где, как, срок), ставит важность (высокая / средняя / низкая). Письма сортируются по важности, внутри неё по сроку.
- **Ничего не теряется.** Состояние пишется в базу только после успешной отправки письма.
  Упал SMTP — на следующем запуске изменения найдутся снова.
- **Тихие сбои невозможны.** Если у источника не нашлось ни одной ссылки (поменялась вёрстка,
  сайт отдал антибот-заглушку), это считается ошибкой. После 3 запусков подряд приходит письмо о сбое.
- **Первый запуск не засыпает почту архивом:** присылается самый свежий документ, остальные
  запоминаются молча (`initial_notify` в конфиге).
- Без ключа DeepSeek, при сбое API или если закончились деньги на балансе письмо всё равно уходит —
  с фрагментом текста или diff и пометкой, почему нет разбора.

## Быстрый старт на Windows

1. Нужен [Python 3.10+](https://www.python.org/downloads/windows/) (в установщике отметьте **Add python.exe to PATH**).
2. Дважды щёлкните **`run.bat`**. При первом запуске он сам:
   создаст окружение `.venv`, установит зависимости, создаст `.env` из `.env.example` и откроет его в Блокноте.
   Впишите `DEEPSEEK_API_KEY` и настройки почты (`SMTP_*`, `MAIL_TO`), сохраните файл и закройте Блокнот.
3. Откроется меню. Первый раз идите по пунктам **1 → 2 → 3 → 4 → 5**, и только потом **7**:

| Пункт | Что делает |
|---|---|
| 1 | **doctor**: проверяет настройки, состояние базы и доступность сайтов, DeepSeek и почтового сервера; секреты не показывает |
| 2 | **check-sources**: показывает, что видит парсер на сайте: сколько ссылок нашёл и какой текст получит агент (базу не трогает) |
| 3 | проверка ключа и модели DeepSeek, расход токенов |
| 4 | тестовое письмо |
| 5 / 6 | пробный запуск с агентом / без него: письмо показывается на экране, ничего не отправляется и не сохраняется |
| 7 | боевой запуск (спрашивает подтверждение) |
| 8 | **автозапуск**: включить ежедневный запуск, посмотреть состояние, выключить |
| 9 / 10 | открыть `.env` / запустить тесты |
| 11 | **сбросить память**: программа забудет прочитанное, письма придут заново (резервная копия сохраняется) |
| 12 | **контрольные вызовы API**: что отвечают методы и что изменилось с прошлого раза (ничего не сохраняет) |
| 13 | **журнал интеграции**: счётчики ошибок с прошлой проверки (ничего не сохраняет) |

Весь ход работы выводится в консоль и пишется в **`logs\sitewatch.log`** (ротация: 5 файлов по 1 МБ).
Если что-то идёт не так, пришлите этот файл. Флаг `-v` добавляет подробности вплоть до сетевых запросов.

`run.bat` принимает и обычные команды: `run.bat doctor`, `run.bat run --dry-run`, `run.bat check-sources`.

## Установка вручную (Linux, macOS)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e .            # для разработки: pip install -e '.[dev]'
cp .env.example .env        # заполнить SMTP и DEEPSEEK_API_KEY
```

Ключ DeepSeek создаётся на [platform.deepseek.com](https://platform.deepseek.com) (раздел API keys),
баланс нужно пополнить. Подробнее о цене — ниже, в разделе «Агент и стоимость».

Для Gmail, Яндекс и Mail.ru в `SMTP_PASSWORD` нужен пароль приложения, а не обычный пароль.

## Запуск

```bash
sitewatch menu                        # интерактивное меню (то же, что открывает run.bat)
sitewatch doctor                      # проверка настроек, состояния и соединений (--offline: без сети)
sitewatch check-sources               # что видит парсер на сайтах; базу не трогает
sitewatch test-email                  # проверить почту
sitewatch test-llm                    # проверить ключ и модель DeepSeek, показать расход токенов
sitewatch run --dry-run               # посмотреть, что бы ушло в письме (ничего не отправляет и не сохраняет)
sitewatch run --dry-run --no-llm      # то же без обращения к DeepSeek
sitewatch run                         # боевой запуск
sitewatch run --source chestny-znak-releases   # только один источник
sitewatch run --no-monitors           # без контрольных вызовов API и чтения журнала
sitewatch probes [--save]             # контрольные вызовы API; --save запоминает ответы как исходные
sitewatch logwatch [--save]           # счётчики ошибок в журнале интеграции
```

Код возврата 1 означает, что не удалось проверить ни один источник или не ушло письмо.

### Автозапуск на Linux (cron)

```cron
# каждый день в 08:30 по Москве (05:30 UTC — непиковый тариф DeepSeek), лог в файл
# (часовой пояс сервера — UTC; для московского времени сервера поставьте 30 8)
30 5 * * * cd /opt/sitewatch && .venv/bin/sitewatch run >> data/run.log 2>&1
```

Файл состояния лежит в `data/state.db` — его нужно сохранять между запусками.

### Автозапуск на Windows

В меню `run.bat` выберите пункт **8** и затем **1**, введите время (по умолчанию 08:30 по часам компьютера). Программа сама
создаст ежедневное задание «sitewatch» в Планировщике заданий (то же из командной строки: `run.bat schedule install --time 08:30`).

- Задание работает, пока вы вошли в Windows. Окно запуска появляется **свёрнутым** на панели задач.
- Если в назначенное время компьютер был выключен, проверка выполнится при ближайшем включении (повторный запуск безопасен:
  без новых изменений письма нет).
- Пункт 8 показывает состояние задания и чем закончился прошлый запуск; **2** выключает автозапуск.
- Каждый запуск пишет в `logs\sitewatch.log`, а при проблемах с источниками приходит письмо-алерт.
- 08:30 по Москве совпадает с непиковым тарифом DeepSeek; для других часовых поясов время можно выбрать любое.

Если компьютер выключают на ночь и на выходные или нужна гарантия, запускайте на сервере, который работает постоянно
(`run.bat auto` на Windows-сервере или cron на Linux).

Вручную через консоль: `schtasks /Create /SC DAILY /ST 08:30 /TN "sitewatch" /TR "C:\sitewatch\run.bat auto"`.

## Сброс памяти: получить письмо заново

Программа помнит прочитанные документы в `data\state.db`, поэтому повторный запуск молчит, пока на сайте ничего не изменилось.
Чтобы письма пришли снова (например, для проверки), выберите в меню пункт **11** (из консоли: `run.bat reset`,
или `run.bat reset --source ID` для одного источника). Перед очисткой создаётся копия `data\state.db.bak`.

Следующий боевой запуск (пункт 7) поведёт себя как самый первый: по каждому списку релизов придёт письмо о самом свежем
документе. Одиночные страницы и PDF при первом запуске запоминаются молча; чтобы письмо пришло и по ним, задайте им
`initial_notify: 1` в `config/sources.yaml`.

Сброс без выбора источника забывает и исходные ответы контрольных вызовов API, и позиции в журналах: следующий запуск
снова запомнит их молча. Сброс одного источника (`--source`) их не трогает.

Вручную то же самое: закройте программу и удалите файл `data\state.db`.

## Добавление нового сайта

Допишите источник в `config/sources.yaml` (все поля описаны в комментариях в файле):

| type | когда использовать |
|---|---|
| `list` | страница-список со ссылками на документы (новости, релизы) |
| `sitemap` | то же, если список подгружается скриптом, а в `sitemap.xml` ссылки есть |
| `page` | одна страница, следим за изменением её текста |
| `pdf` | один PDF-файл (например, спецификация API): следим за изменением текста |
| `text` | текстовый файл: JSON/OpenAPI-спецификация, YAML; адрес `file:///C:/...` читает файл с диска |
| `telegram` | публичный Telegram-канал (`https://t.me/s/имя_канала`): каждое сообщение — документ |

Поле `focus` — подсказка агенту, что именно важно вашим читателям на этом сайте. Поле `follow_pdf: true` включает чтение PDF,
на которые ссылаются страницы источника (см. «PDF»).

## Агент и стоимость

Агент вызывается только для найденных изменений (обычно 0–2 раза в день, чаще всего вообще не
вызывается). Используется DeepSeek через его API (`https://api.deepseek.com`, JSON-режим).

| Настройка | Значение по умолчанию | Зачем |
|---|---|---|
| `LLM_MODEL` | `deepseek-flash` (V4.1 Flash) | лучшее соотношение цены и качества для пересказа и извлечения фактов |
| `LLM_THINKING` | `off` | режим размышлений для пересказа не нужен, а его токены платные |

Цены на странице [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/) на момент
написания (за 1 млн токенов; в непиковые часы вдвое дешевле):

| Модель | Вход (кэш мимо) | Выход |
|---|---|---|
| `deepseek-flash` | 0,30 $ в пик / 0,15 $ вне пика | 1,20 $ / 0,60 $ |
| `deepseek-v4-pro` | 1,32 $ / 0,66 $ | 3,96 $ / 1,98 $ |

Оценка для нашей нагрузки (страница релиза — примерно 6–12 тыс. входных токенов, ответ — около 600):
**порядка 0,2–0,5 цента за страницу на Flash**, то есть несколько центов в месяц; на Pro примерно
в 4,4 раза больше, тоже центы. Реальный расход показывает `sitewatch test-llm` и личный кабинет DeepSeek.
Пиковые часы DeepSeek — 01:00–04:00 и 06:00–10:00 UTC по будням, расписание cron выше в них не попадает.

Если Flash пропустит важное, можно сравнить на тех же страницах без риска для рассылки:
`LLM_MODEL=deepseek-v4-pro sitewatch run --dry-run`.

Страницы сайтов отправляются в API DeepSeek (серверы в Китае), поэтому подключайте только публичные
источники — для закрытых документов такой вариант не подходит.

## PDF

- Источник `type: pdf` — один файл; в списках (`type: list`) ссылки на `.pdf` тоже читаются как PDF.
- Сравнивается **текст**, а не байты: пересборка файла без правок ложной тревоги не даёт. Номера страниц и колонтитулы,
  повторяющиеся на страницах, убираются, поэтому между версиями в разницу попадают только настоящие правки. Колонтитулы
  сворачиваются в одну служебную строку `[Колонтитулы: …]` в конце текста: смена версии, указанной только в шапке, остаётся заметной.
- Первый запуск запоминает PDF молча (письмо про весь документ вам не нужно). Дальше агент получает не весь документ, а
  разницу версий, и присылает разбор: что изменилось, сроки, важность.
- Скан без текстового слоя прочитать нельзя (распознавание изображений не поддерживается): программа скажет об этом
  прямо. Файлы больше `SITEWATCH_MAX_PDF_MB` (по умолчанию 50 МБ) пропускаются.
- Проверить, что видит программа в PDF: пункт 2 меню («проверка источников») покажет заголовок и начало текста.

### PDF по ссылкам со страниц (`follow_pdf`)

Инструкции и памятки часто лежат не на отдельной странице, а PDF-файлом, на который ссылается статья или релиз. Для таких
источников задайте `follow_pdf: true`: PDF, на которые ссылается страница, читаются как **отдельные документы** (новый файл —
новый документ, правка файла — «документ обновлён» с разбором разницы), а в письме видно, на какой странице файл найден.

- Берутся только ссылки из основного блока страницы, не из меню и подвала (там лежат политики и оферты). Если основной блок
  определился неверно, задайте `content_selector`.
- `max_pdf_links` — сколько PDF обрабатывать на странице (по умолчанию 5), `pdf_pattern` — регулярное выражение, какие ссылки
  брать (если задано, расширение `.pdf` не обязательно: подойдёт и `/download?id=12`).
- Для списков (`list`) и `sitemap` это относится к каждой странице-документу, для `page` — к самой странице. PDF, которые
  не скачались или оказались сканами, пропускаются с предупреждением в журнале и не считаются сбоем источника.
- Известные PDF проверяются на правки при каждом запуске, поэтому много страниц с `recheck_latest` и большими файлами — это
  больше трафика.
- Пункт 2 меню покажет, какие PDF-ссылки программа нашла на странице.

Что нашлось по поиску: отдельной PDF-памятки Честного ЗНАКа именно по мясу и рыбе в открытом доступе нет, а инструкции лежат в
разделах «База знаний» и «Сообщество» на markirovka.ru и во вложениях к релизам. Поэтому PDF ищутся там, где они встречаются
(`follow_pdf`), а не по фиксированным адресам. Если найдёте стабильный адрес нужного PDF, добавьте его источником `type: pdf`.

## Тема писем: только мясо и рыба

В `config/sources.yaml` блок `scope` описывает, что вам интересно. Агент выписывает из документа **только** это, а документ,
где ничего подходящего нет (например, релиз только про молоко и воду или общий релиз API), в письмо не попадает.

```yaml
scope:
  interests: Мясо и мясная продукция, рыба и рыбная продукция, мясные и рыбные консервы, Меркурий (ВетИС)...
  include_general: false    # по умолчанию: только то, что прямо про мясо и рыбу
  glossary: config/glossary.yaml
```

Так выглядит одна запись дайджеста (иначе письмо не прочесть за минуту):

```
[ВЫСОКАЯ] Что нового в системе с 22.09.2026 (новый документ)
  Что:   В отчёт о нанесении для мяса добавлено обязательное поле «масса нетто».
  Где:   - Отчёт о нанесении → обработка ОтчётНанесение, регистр НанесениеКодов
         - поле «масса нетто»
  Как:   передавать массу нетто в отчёте о нанесении
  Срок:  01.09.2026 — поле становится обязательным
```

- Каждому документу агент ставит отметку: **«прямо»** (про вашу тему), **«общее»** (про всех) или **«не относится»**. При
  `include_general: false` в письмо идёт только «прямо». Общие изменения для всех товарных групп (авторизация, формат запросов,
  смена хостов API) при этом в письмо не попадают: за ними следят контрольные вызовы API и счётчики журнала (ниже), которые
  срабатывают независимо от товарной группы. Поставьте `include_general: true`, если хотите видеть и общие релизы.
- Отфильтрованное не пропадает бесследно: в конце письма перечислено, что не вошло и почему. Если агент ошибся, видно сразу;
  тему можно уточнить в `interests`.
- Если агент не смог разобрать документ (нет ключа, закончились деньги), письмо уйдёт с фрагментом: судить о теме без разбора нельзя.
- Состояние сохраняется и для отфильтрованного: завтра оно не повторится.

### Таблица «что менять» и тема письма

`config/glossary.yaml`: «метод API или термин -> где менять в вашей системе (ТАЛАРИКС MES)». Агент выбирает из таблицы, чего касается
изменение, и письмо отвечает на вопрос «что менять», а не только «что изменилось»:

```
Тема: [Мониторинг] срок: 01.09.2027, затронуто: авторизация и токен — Что нового в системе с 22.09.2026
...
Где:   - Авторизация и токен → обработка ПолучитьТокен, регистр ТокеныДоступа
```

Заполните колонку `where` своими объектами конфигурации и обработками. Пока она пуста, в письме будет только название записи.
Названия, которых нет в таблице, программа отбрасывает, поэтому агент не может «придумать» несуществующий объект.
Проверить заполнение: пункт 1 меню (doctor).

## robots.txt

Перед загрузкой программа читает `robots.txt` сайта и не ходит туда, где автоматическая загрузка запрещена. Режим задаётся
`SITEWATCH_ROBOTS` в `.env` и (для одного источника) полем `robots:` в `sources.yaml`:

| Режим | Что делает |
|---|---|
| `respect` (по умолчанию) | запрещённое не загружается; источник считается недоступным и в журнале объяснено почему |
| `warn` | загружает, но пишет предупреждение в журнал |
| `off` | robots.txt не проверяется |

Если сайт запретил нужный вам раздел, а вы вправе его забирать (например, вы клиент сервиса), разрешите это явно у конкретного
источника, а не глобально. Пункт 2 меню показывает вердикт robots.txt для каждого источника и просьбу сайта о паузе между запросами.

## Источники

Все источники в `config/sources.yaml` включены; выключенных «на потом» в поставке нет. Каждый источник либо даёт агенту мясо и рыбу
и тогда он в списке, либо его нет.

| Источник | Что даёт агенту |
|---|---|
| `chestny-znak-releases` | релизы «Что нового в системе» на честныйзнак.рф + PDF из релизов |
| `kontur-markirovka-news`, `kontur-mercury-news` | новости Контур.Маркировки и Контур.Меркурия: сроки и правила по мясу, рыбе, консервам, ВСД |
| `markirovka-kb-myaso`, `-konservy`, `-ikra` | «База знаний» markirovka.ru по товарным группам + PDF к статьям |
| `markirovka-community-myaso`, `-konservy`, `-ikra` | статьи Честного ЗНАКа по группам: этапы, сроки, инструкции + PDF |

Что убрано и почему:

- **Сообщество разработчиков на markirovka.ru** (вопросы и ответы по API): пользовательские вопросы, из них агенту нечего взять
  по мясу и рыбе, а изменения API ловят контрольные вызовы и счётчики журнала.
- **Telegram `oms_mdlp_notif`**: канал МДЛП (лекарства), к мясу и рыбе не относится.
- **Справка ВетИС, страница «Последние изменения»**: список заголовков правок вики, агент не может вывести из него ни срок, ни действие,
  а сама страница меняется каждый день. Меркурий покрывают новости Контура. Если найдёте стабильный раздел с новостями ВетИС
  или PDF с руководством, добавьте его источником.

**Адреса взяты из поиска, а с облачной среды сайты недоступны, поэтому проверить их там нельзя.** Перед первым боевым запуском
выполните пункт 2 меню: он покажет по каждому источнику, нашёл ли парсер ссылки и нормальный текст, и вердикт `robots.txt`.
Источник, который не читается, поправьте (`link_pattern`) или удалите. Если источник перестанет читаться позже, на третий запуск подряд
в письме придёт предупреждение.

## Контрольные вызовы API

Не все изменения API объявляют заранее. `config/probes.yaml` описывает 5–10 методов вашей интеграции; раз в сутки (вместе с основным
запуском) программа дёргает их и сравнивает ответ с прошлым разом. Раздел **«Сигналы API»** в письме появляется, если:

| Сигнал | Что значит |
|---|---|
| HTTP 410 | метод отключён (сообщается и при первом запуске) |
| перенаправление на другой хост | сменился адрес сервера |
| статус ответа изменился | например, 401 → 404: метод убрали или переименовали |
| новый текст ошибки при том же статусе | например, «Токен не действителен» → «Устаревшее API» |
| изменился состав полей JSON-ответа | исчезло поле (опасно) или появилось новое (информационно) |
| метод не отвечает 2 запуска подряд | недоступен (один сбой не считается: бывают проблемы сети) |

Как это настроить:

1. В `.env` задайте `TRUE_API_BASE` (лучше тестовый контур), по возможности `TRUE_API_TOKEN` и `TRUE_API_TEST_KM`. Пока адрес не задан,
   пробы пропускаются без сигналов.
2. Подставьте в `config/probes.yaml` свои методы (авторизация, `cises/info`, документы, отчёт о нанесении). Примеры там лежат в духе TrueAPI
   и **их адреса и тела запросов нужно сверить с вашей интеграцией**: из облачной среды проверить их было нельзя.
3. Токен можно не хранить в `.env`, а получать командой (`token.command`): она должна печатать токен в последней строке вывода.
   Подпись УКЭП программа сама не делает, нужна готовая команда или утилита из вашей интеграции. Без токена методы с авторизацией
   проверяются анонимно: видны статус и текст ошибки (обычно 401), и сигнал сработает, когда они изменятся.
4. Пункт 12 меню (или `run.bat probes`) показывает ответы и сигналы, ничего не сохраняя. `run.bat probes --save` запоминает сегодняшние
   ответы как исходные; иначе это сделает первый боевой запуск.

Подробности: исходное состояние запоминается отдельно для режимов «с токеном» и «без токена». После сигнала новое состояние становится
исходным и дальше молчит, пока ответ снова не изменится. Если письмо не ушло, состояние не сохраняется, и сигнал придёт при
следующем запуске. Токен в письма, журнал и сообщения не попадает. Перенаправления не выполняются: смена хоста сама по себе сигнал.
Пробы ходят в API по-настоящему даже в пробном запуске (`--dry-run`), но ничего не меняют в системе: используйте тестовые данные.

## Счётчики ошибок в журнале интеграции

В боевом журнале рост строк «Устаревшее API» или «Токен не действителен» означает, что API уже поменяли или вот-вот отключат старую версию.
`config/logwatch.yaml` описывает журналы (пути, маски со звёздочкой) и шаблоны строк. Раз в сутки программа читает только то, что дописано
с прошлого раза, считает совпадения и добавляет в письмо **сигнал**, если их не меньше `min_count` и не меньше `growth` × обычного уровня
(среднее за прошлые проверки). «Устаревшее API» в норме не встречается, поэтому любая строка уже сигнал; «Токен не действителен» бывает
и в обычной работе, поэтому порог выше.

- Первый запуск историю не читает: запоминает только размер файла. Ротация (новый файл по дате или усечённый старый) распознаётся.
- Кодировка определяется сама (UTF-8, иначе cp1251) или задаётся полем `encoding`.
- В письмо попадают только числа и имена файлов, строки журнала нет: в них бывают токены и персональные данные.
- Нужно указать реальные пути в `paths`. Пока файлов нет, проверка молча пропускается. Пункт 13 меню (или `run.bat logwatch`) показывает
  счётчики, ничего не сохраняя; `--save` запоминает текущую позицию.

## Что нужно от вас

1. `.env`: ключ DeepSeek, почта; `TRUE_API_BASE`, при возможности токен и тестовый код маркировки.
2. Меню → пункт **2**: убедиться, что парсер видит ссылки и текст у всех источников; лишние удалить.
3. `config/probes.yaml`: свои методы (5–10) вместо примеров; `config/logwatch.yaml`: пути к журналам интеграции.
4. `config/glossary.yaml`: колонка `where` (объект конфигурации и обработка в ТАЛАРИКС MES) — без неё «Где» в письме будет только
   названием метода.
5. Пункт **5** меню (пробный запуск), затем **7** и автозапуск (**8**).

## Если что-то не настроено или не работает

Программа устроена так, чтобы одна неполадка не лишала вас остального: из неработающей части просто нет информации.

| Ситуация | Что происходит |
|---|---|
| Источник не открывается (сайт недоступен, 403/404, антибот-заглушка, нет ссылок по шаблону, битый sitemap, закрыто `robots.txt`, нет файла `file://`, непредвиденная ошибка разбора) | в этот запуск источник пропускается, остальные работают как обычно; причина видна в консоли и `logs\sitewatch.log`. Если так три запуска подряд, в письме приходит **одно** предупреждение с причиной. Когда источник заработает, он начнёт читаться сам (как при первом запуске: `initial_notify`) |
| Не скачался один PDF или он оказался сканом | пропускается только этот файл (предупреждение в журнале), страница с остальными файлами обрабатывается |
| Все источники недоступны | письмо о сбое, код возврата 1; падения нет |
| Не задан ключ DeepSeek, закончились деньги, сбой API | письмо всё равно уходит: с фрагментами текста и пометкой, почему нет разбора |
| Нет `probes.yaml`, не задан `TRUE_API_BASE`, нет токена | проба пропускается без сигналов; без токена методы проверяются анонимно |
| Нет `logwatch.yaml` или по указанным путям нет файлов | проверка журнала пропускается; когда файлы появятся, первый раз они только запомнятся (старая история не считается) |
| Ошибка синтаксиса в `probes.yaml` или `logwatch.yaml` | в письме предупреждение «проверка не удалась» с причиной; документы и вторая проверка работают |
| Письмо не ушло (SMTP) | состояние не сохраняется, при следующем запуске всё найдётся заново, ничего не теряется |

Запуск **останавливается** только если нет смысла продолжать: не заданы настройки почты (кроме пробного режима `--dry-run`),
ошибка синтаксиса в `sources.yaml` или в таблице `glossary.yaml`, в `sources.yaml` указан отсутствующий файл таблицы, нет ни одного
источника. Во всех этих случаях программа пишет понятную причину, а не трассировку.

## Что важно знать

- Тексты страниц передаются агенту как данные, а не инструкции (защита от prompt injection);
  слишком длинный документ не режется молча — в письме будет пометка.
- Парсер подгоняется под вёрстку: если в письмо попадает меню или баннеры, задайте
  `content_selector`; если в тексте есть счётчики и даты, меняющиеся при каждой загрузке, —
  `ignore_regex`.
- Закрытые разделы (личный кабинет, API-документация для зарегистрированных участников) этот
  вариант не покрывает: нужна авторизация.
- Скрипт ходит редко (раз в сутки, с паузой между запросами). Если сайт отдаёт 403 или заглушку,
  запускайте с российского IP.

```bash
pytest
```

Тесты используют макеты страниц и подменённые сеть, почту и API DeepSeek; проверяют сценарии
