# sitewatch — мониторинг обновлений документации

Раз в сутки проверяет сайты из списка, находит новые и изменённые документы, просит агента
(DeepSeek) разобрать их по-русски и присылает **один дайджест на почту**. Если обновлений нет —
письма нет. Первый источник — раздел «Что нового в системе» на честныйзнак.рф; новые сайты
добавляются записью в `config/sources.yaml` без правки кода.

## Как это устроено

```
sources.yaml → Fetch → Извлечение текста → Сравнение с базой (SQLite) → Агент-аналитик → Письмо
                                           хэш + diff, новые ссылки      DeepSeek, JSON  SMTP
```

- **Скрипт** отвечает за «забрать, сравнить, запомнить»: дёшево и без галлюцинаций.
- **Агент** подключается только когда изменение найдено: объясняет суть, сроки, кого касается,
  ставит важность (высокая / средняя / низкая). Письма сортируются по важности.
- **Ничего не теряется.** Состояние пишется в базу только после успешной отправки письма.
  Упал SMTP — на следующем запуске изменения найдутся снова.
- **Тихие сбои невозможны.** Если у источника не нашлось ни одной ссылки (поменялась вёрстка,
  сайт отдал антибот-заглушку), это считается ошибкой. После 3 запусков подряд приходит письмо о сбое.
- **Первый запуск не засыпает почту архивом:** присылается самый свежий документ, остальные
  запоминаются молча (`initial_notify` в конфиге).
- Без ключа DeepSeek, при сбое API или если закончились деньги на балансе письмо всё равно уходит —
  с фрагментом текста или diff и пометкой, почему нет разбора.

## Быстрый старт на Windows

1. Нужен [Python 3.10+](https://www.python.org/downloads/windows/) (в установщике отметьте **Add python.exe to PATH**).
2. Дважды щёлкните **`run.bat`**. При первом запуске он сам:
   создаст окружение `.venv`, установит зависимости, создаст `.env` из `.env.example` и откроет его в Блокноте.
   Впишите `DEEPSEEK_API_KEY` и настройки почты (`SMTP_*`, `MAIL_TO`), сохраните файл и закройте Блокнот.
3. Откроется меню. Первый раз идите по пунктам **1 → 2 → 3 → 4 → 5**, и только потом **7**:

| Пункт | Что делает |
|---|---|
| 1 | **doctor**: проверяет настройки, состояние базы и доступность сайтов, DeepSeek и почтового сервера; секреты не показывает |
| 2 | **check-sources**: показывает, что видит парсер на сайте: сколько ссылок нашёл и какой текст получит агент (базу не трогает) |
| 3 | проверка ключа и модели DeepSeek, расход токенов |
| 4 | тестовое письмо |
| 5 / 6 | пробный запуск с агентом / без него: письмо показывается на экране, ничего не отправляется и не сохраняется |
| 7 | боевой запуск (спрашивает подтверждение) |
| 8 | **автозапуск**: включить ежедневный запуск, посмотреть состояние, выключить |
| 9 / 10 | открыть `.env` / запустить тесты |

Весь ход работы выводится в консоль и пишется в **`logs\sitewatch.log`** (ротация: 5 файлов по 1 МБ).
Если что-то идёт не так, пришлите этот файл. Флаг `-v` добавляет подробности вплоть до сетевых запросов.

`run.bat` принимает и обычные команды: `run.bat doctor`, `run.bat run --dry-run`, `run.bat check-sources`.

## Установка вручную (Linux, macOS)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e .            # для разработки: pip install -e '.[dev]'
cp .env.example .env        # заполнить SMTP и DEEPSEEK_API_KEY
```

Ключ DeepSeek создаётся на [platform.deepseek.com](https://platform.deepseek.com) (раздел API keys),
баланс нужно пополнить. Подробнее о цене — ниже, в разделе «Агент и стоимость».

Для Gmail, Яндекс и Mail.ru в `SMTP_PASSWORD` нужен пароль приложения, а не обычный пароль.

## Запуск

```bash
sitewatch menu                        # интерактивное меню (то же, что открывает run.bat)
sitewatch doctor                      # проверка настроек, состояния и соединений (--offline: без сети)
sitewatch check-sources               # что видит парсер на сайтах; базу не трогает
sitewatch test-email                  # проверить почту
sitewatch test-llm                    # проверить ключ и модель DeepSeek, показать расход токенов
sitewatch run --dry-run               # посмотреть, что бы ушло в письме (ничего не отправляет и не сохраняет)
sitewatch run --dry-run --no-llm      # то же без обращения к DeepSeek
sitewatch run                         # боевой запуск
sitewatch run --source chestny-znak-releases   # только один источник
```

Код возврата 1 означает, что не удалось проверить ни один источник или не ушло письмо.

### Автозапуск на Linux (cron)

```cron
# каждый день в 08:30 по Москве (05:30 UTC — непиковый тариф DeepSeek), лог в файл
# (часовой пояс сервера — UTC; для московского времени сервера поставьте 30 8)
30 5 * * * cd /opt/sitewatch && .venv/bin/sitewatch run >> data/run.log 2>&1
```

Файл состояния лежит в `data/state.db` — его нужно сохранять между запусками.

### Автозапуск на Windows

В меню `run.bat` выберите пункт **8** и затем **1**, введите время (по умолчанию 08:30 по часам компьютера). Программа сама
создаст ежедневное задание «sitewatch» в Планировщике заданий (то же из командной строки: `run.bat schedule install --time 08:30`).

- Задание работает, пока вы вошли в Windows. Окно запуска появляется **свёрнутым** на панели задач.
- Если в назначенное время компьютер был выключен, проверка выполнится при ближайшем включении (повторный запуск безопасен:
  без новых изменений письма нет).
- Пункт 8 показывает состояние задания и чем закончился прошлый запуск; **2** выключает автозапуск.
- Каждый запуск пишет в `logs\sitewatch.log`, а при проблемах с источниками приходит письмо-алерт.
- 08:30 по Москве совпадает с непиковым тарифом DeepSeek; для других часовых поясов время можно выбрать любое.

Если компьютер выключают на ночь и на выходные или нужна гарантия, запускайте на сервере, который работает постоянно
(`run.bat auto` на Windows-сервере или cron на Linux).

Вручную через консоль: `schtasks /Create /SC DAILY /ST 08:30 /TN "sitewatch" /TR "C:\sitewatch\run.bat auto"`.

## Добавление нового сайта

Допишите источник в `config/sources.yaml` (все поля описаны в комментариях в файле):

| type | когда использовать |
|---|---|
| `list` | страница-список со ссылками на документы (новости, релизы) |
| `sitemap` | то же, если список подгружается скриптом, а в `sitemap.xml` ссылки есть |
| `page` | одна страница, следим за изменением её текста |
| `pdf` | один PDF-файл (например, спецификация API): следим за изменением текста |

Поле `focus` — подсказка агенту, что именно важно вашим читателям на этом сайте.

## Агент и стоимость

Агент вызывается только для найденных изменений (обычно 0–2 раза в день, чаще всего вообще не
вызывается). Используется DeepSeek через его API (`https://api.deepseek.com`, JSON-режим).

| Настройка | Значение по умолчанию | Зачем |
|---|---|---|
| `LLM_MODEL` | `deepseek-flash` (V4.1 Flash) | лучшее соотношение цены и качества для пересказа и извлечения фактов |
| `LLM_THINKING` | `off` | режим размышлений для пересказа не нужен, а его токены платные |

Цены на странице [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/) на момент
написания (за 1 млн токенов; в непиковые часы вдвое дешевле):

| Модель | Вход (кэш мимо) | Выход |
|---|---|---|
| `deepseek-flash` | 0,30 $ в пик / 0,15 $ вне пика | 1,20 $ / 0,60 $ |
| `deepseek-v4-pro` | 1,32 $ / 0,66 $ | 3,96 $ / 1,98 $ |

Оценка для нашей нагрузки (страница релиза — примерно 6–12 тыс. входных токенов, ответ — около 600):
**порядка 0,2–0,5 цента за страницу на Flash**, то есть несколько центов в месяц; на Pro примерно
в 4,4 раза больше, тоже центы. Реальный расход показывает `sitewatch test-llm` и личный кабинет DeepSeek.
Пиковые часы DeepSeek — 01:00–04:00 и 06:00–10:00 UTC по будням, расписание cron выше в них не попадает.

Если Flash пропустит важное, можно сравнить на тех же страницах без риска для рассылки:
`LLM_MODEL=deepseek-v4-pro sitewatch run --dry-run`.

Страницы сайтов отправляются в API DeepSeek (серверы в Китае), поэтому подключайте только публичные
источники — для закрытых документов такой вариант не подходит.

## PDF

- Источник `type: pdf` — один файл; в списках (`type: list`) ссылки на `.pdf` тоже читаются как PDF.
- Сравнивается **текст**, а не байты: пересборка файла без правок ложной тревоги не даёт. Номера страниц и колонтитулы,
  повторяющиеся на страницах, убираются, поэтому между версиями в разницу попадают только настоящие правки. Колонтитулы
  сворачиваются в одну служебную строку `[Колонтитулы: …]` в конце текста: смена версии, указанной только в шапке, остаётся заметной.
- Первый запуск запоминает PDF молча (письмо про весь документ вам не нужно). Дальше агент получает не весь документ, а
  разницу версий, и присылает разбор: что изменилось, сроки, важность.
- Скан без текстового слоя прочитать нельзя (распознавание изображений не поддерживается): программа скажет об этом
  прямо. Файлы больше `SITEWATCH_MAX_PDF_MB` (по умолчанию 50 МБ) пропускаются.
- Проверить, что видит программа в PDF: пункт 2 меню («проверка источников») покажет заголовок и начало текста.

## Что важно знать

- Тексты страниц передаются агенту как данные, а не инструкции (защита от prompt injection);
  слишком длинный документ не режется молча — в письме будет пометка.
- Парсер подгоняется под вёрстку: если в письмо попадает меню или баннеры, задайте
  `content_selector`; если в тексте есть счётчики и даты, меняющиеся при каждой загрузке, —
  `ignore_regex`.
- Закрытые разделы (личный кабинет, API-документация для зарегистрированных участников) этот
  вариант не покрывает: нужна авторизация.
- Скрипт ходит редко (раз в сутки, с паузой между запросами). Если сайт отдаёт 403 или заглушку,
  запускайте с российского IP.

## Тесты

```bash
pytest
```

Тесты используют макеты страниц и подменённые сеть, почту и API DeepSeek; проверяют сценарии
первого запуска, нового релиза, правки страницы, сбоя отправки, лавины новых документов,
пустого списка и алертов.

## Структура

```
run.bat                 запуск на Windows: окружение, зависимости, .env, меню
sitewatch/  config.py · fetch.py · extract.py · store.py · analyze.py · notify.py · pipeline.py
            cli.py · menu.py · doctor.py · scheduler.py · ui.py
config/sources.yaml     источники
logs/                   журнал работы (не попадает в git)
data/                   состояние между запусками (не попадает в git)
tests/                  pytest
```
